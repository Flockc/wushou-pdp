PDP · 行为风格自评

开始之前，先说清楚三件事

  1. 凭第一反应选。题目没有对错，也没有「更好的性格」，只有更接近你日常状态的那个选项。

五只动物，五种默认反应

PDP 把行为风格分成四个可观测维度：支配、表达、耐心、精确。第五种「变色龙」不是题目选项， 而是当四种倾向都不突出时，由判定规则给出的一种结果。下面是它们的完整画像，以及和它们协作时最省力的方式。

作品介绍 · About

一个小测评，为什么值得做成两个版本

《五兽之镜》是一套 PDP 行为风格自评工具。它有两个形态：一个跑在千星奇域编辑器里的 UGC 关卡， 一个跑在浏览器里的网页应用。前者证明这套交互能在游戏里成立，后者让任何人都能零门槛地看到它。

01

创作缘起

起点是一个很具体的场景：团队里反复出现同一种摩擦——有人觉得对方「不推进」，有人觉得对方「太着急」。 两边都没错，只是默认反应不同。市面上的性格测评不少，但大多是长问卷、要注册、结果是一段无法验证的形容词。

于是想做一个更轻的东西：15 题、3 分钟、结果可解释、可以当场分享。 选择 PDP 五型，是因为动物比喻天然适合口头传播——「他是孔雀」比「他的表达维度得分较高」更容易在会议室里说出口。

后来又把它做进了千星奇域。原因也很直接：如果这套交互只能在网页里成立，它只是一个问卷； 能在一个游戏关卡里被玩家主动点开、做完、截图发出去，它才更接近「作品」。

02

四个设计取舍

Q1为什么作答时不显示每个选项对应的维度？

一旦标出「这题选 A 加老虎分」，测评就变成了填空题。隐藏维度会让个别题目看起来「四个都不太像我」， 但能换来更真实的作答。维度信息在结果页的「答题回顾」里完整公开，想知道随时能看。

Q2为什么用「极差 ≤ 2」判变色龙，而不是直接取最高分？

15 题、四个维度，平均每题每维约 3.75 分。如果只取最高分，一个 4/4/4/3 的人会被判成老虎， 但这四分之差更像噪声而非倾向。设定「最高减最低 ≤ 2」判为变色龙，是为了给「四项都不弱」的人一个诚实的出口。 阈值放在脚本与数据层各一处常量里，可以按场景调整。

Q3为什么同时做键盘、鼠标、手柄三套输入？

沙箱版的原始约束是「光标事件必须容器开 showCursor 才生效」，而手柄导航是另一套焦点系统。 只做鼠标，等于在手柄玩家那里直接失效；只做按键，又不适合手机端。 所以选项区同时挂了光标点击与 1–4 键，切屏时主动设置手柄焦点，Web 版则把这三类输入映射成同一套动作。

Q4为什么网页版坚持零依赖？

评审打开一个链接，不该先等 3MB 的框架下载完。整套页面只用原生 HTML / CSS / JavaScript， 没有构建步骤、没有 CDN 依赖，断网也能跑；同时也让这份代码可以直接作为静态站点托管。

03

功能一览

八项功能都指向同一个目标：让「做完一次测评」这件事足够顺，顺到愿意把它发给别人。

15 题四选一

每题四个选项分别对应老虎 / 孔雀 / 考拉 / 猫头鹰，作答时不显示维度，避免「照着答案选」。

极差阈值判定

不只取最高分：最高与最低分相差 ≤ 2 时判为变色龙型，专门容纳「四项都不弱」的人。

四维可视化

雷达图 + 四条得分条 + 一条均衡度，让「为什么是这个结果」可被解释，而不是一个黑箱标签。

键盘 / 鼠标 / 触屏

支持 1–4 键作答、← 键回看上一题、Enter 开始；移动端为整块可点区域，无悬停依赖。

断点续答

进度写入 localStorage，刷新或误关页面后可从第 n 题继续，也可一键清空重来。

结果分享卡

一键生成 1080×1440 的结果图并下载，适合直接发群、发朋友圈，不必截图裁切。

答题回顾

结果页可展开每一题的选择与对应维度，方便复盘「我是不是被某一题带偏了」。

纯本地计算

无账号、无后端、无埋点，作答数据不离开浏览器；断网也能完成整套测评。

04

技术实现

网页版

  • 原生 HTML + CSS + JavaScript，零第三方库
  • Hash 路由，单页六视图，无刷新切换
  • CSS 变量管理五型配色，响应式断点 1080 / 860 / 620
  • localStorage 保存进度，刷新可续答
  • Canvas 生成 1080×1440 结果分享卡
  • SVG 手绘雷达图与全部图标，无外部图片

千星沙箱版

  • Lua 5.3 客户端脚本，657 行，单文件七层结构
  • 53 个客户端控件，全部编辑期预置，不依赖动态创建
  • 0 个服务端节点，全部计算在客户端完成
  • 字段直读直写（text / fillAmount / imageColor），无 setter
  • 生命周期必须为全局函数：OnInit / OnStart / OnDisable / OnDestroy
  • 脚本需先在资源管理器建立映射，再挂到容器控件的脚本页签

沙箱端的接口名均取自官方《客户端控件API文档》《客户端控件和客户端脚本》原文； 详细控件清单与搭建步骤见随作品提交的《控件配置清单》与《搭建操作手册》。

06

边界与数据

它不是心理诊断工具。PDP 描述的是工作情境下的行为倾向，不测量能力、智力或心理健康水平。

它不适合作为筛选依据。不应用于招聘淘汰、绩效评定或任何单方面的人事决定。

它不收集作答内容。网页版无账号、无后端，也不接入任何第三方统计脚本；访问次数与作答结果都只存在于你本机的 localStorage，清空浏览器数据即消失。

使用场景 · Scenarios

它最适合被用在「需要开口聊」的场合

这套工具解决的从来不是「测出你是什么人」，而是给一群人一个不尴尬的开场。 下面是五个已经想清楚的具体用法，包含适用对象、真实痛点和主持提示。

01

团队破冰与新人融入

10 人以内的小团队 / 项目组

每人各自做完 15 题，把结果页的分享卡发到群里，用五种动物代替性格标签，10 分钟完成一次有信息量的互相认识。

真实痛点

自我介绍环节往往只剩「我叫什么、我负责什么」，很难形成真实协作预期。

主持提示

建议由主持人先公开自己的结果，降低防御感。

02

管理者的一对一沟通

带 3–10 人团队的基层管理者

用结果页的「注意盲区」与「协作提示」两段，作为一对一沟通的破题材料，把「你怎么这样」换成「你需要什么」。

真实痛点

同一套沟通方式对不同下属效果差异极大，但缺少可复用的解释框架。

主持提示

定位是沟通辅助，不作为绩效或晋升依据。

03

求职与自我盘点

应届生 / 转行者 / 准备述职的人

做完后看四项得分的相对高低，而不是只看一个标签；把「核心优势」翻译成简历里的具体行为证据。

真实痛点

知道自己的经历，但说不清自己的行为风格与适配岗位。

主持提示

结果不能替代真实项目复盘，只提供提问角度。

04

课堂、社团与工作坊

高校社团 / 职业规划课 / 团建活动

纯前端、无需登录、手机打开即用；投屏演示 + 各自手机作答，主持人按五种类型现场分组讨论。

真实痛点

现场互动工具要么太重（要注册、要收费），要么太轻（只是投票）。

主持提示

全部计算在本地完成，不收集任何作答数据。

05

游戏内的轻量互动

千星奇域 UGC 关卡玩家

千星沙箱版把同一套题做成纯客户端控件 UI 关卡，零服务端节点、单局 3 分钟，可作为大厅里的休闲交互点。

真实痛点

UGC 关卡多为动作或解谜，缺少「停下来聊聊自己」的节奏。

主持提示

双端同题库、同阈值，结果口径一致。

主持指南

一场 20 分钟的团队工作坊，可以这样跑

00:00

三、作品简介（约 300 字）

《五兽之镜》是一套基于 PDP 四维模型的轻量行为风格自评工具。它把支配、表达、耐心、精确四个维度，对应为老虎、孔雀、考拉、猫头鹰四种动物，并用「极差 ≤ 2 判为变色龙」的规则，为四项均衡的人保留一个诚实的出口。

作品包含两个形态。千星沙箱版是一个纯客户端控件 UI 的 UGC 关卡：53 个控件、657 行 Lua 脚本、零服务端节点，支持鼠标、键盘与手柄三套输入。网页版用原生 HTML/CSS/JS 重做信息架构，补上四维雷达图、逐题回顾、断点续答与 1080×1440 结果分享卡。

两端共用同一份题库、同一套判定参数与同一组配色，结果口径一致。全部计算在本地完成，不收集任何作答数据。它适合团队破冰、管理者一对一、求职自省与课堂工作坊——目标不是贴标签，而是给一群人一个不尴尬的开场。

四、创作灵感

起点是一个很具体的团队摩擦：有人觉得对方「不推进」，有人觉得对方「太着急」，两边都没错，只是默认反应不同。市面上的测评要么太长，要么结果是一段无法验证的形容词。

于是想做一件更轻的事：15 题、3 分钟、结果可解释、当场能分享。动物比喻的好处是它能在会议室里被说出口——「他是孔雀」比「他的表达维度得分较高」更容易让人接话。

把它做进千星奇域，则是因为：如果这套交互只能在网页里成立，它只是一个问卷；能在一个游戏关卡里被玩家主动点开、做完、截图发出去，它才更像一个作品。

五、功能清单

  • 15 题四选一，作答时隐藏维度，避免照着答案选
  • 四维计分 + 极差阈值判定，输出主类型与均衡度
  • 结果页：雷达图、四条得分条、优势 / 盲区 / 建议
  • 逐题回顾：每题选择与对应维度完整公开
  • 键盘 1–4 作答、← 回看、Enter 开始；移动端整块可点
  • localStorage 断点续答与一键清空
  • Canvas 生成 1080×1440 结果分享卡并下载
  • 五型图鉴与协作对照表
  • 纯本地计算，无账号、无后端、无埋点

六、使用场景

1. 团队破冰与新人融入。每人各自做完，把结果卡发到群里，用五种动物代替性格标签，10 分钟完成一次有信息量的互相认识。

2. 管理者的一对一沟通。用「注意盲区」与「协作提示」两段作为破题材料，把「你怎么这样」换成「你需要什么」。

3. 求职与自我盘点。看四项得分的相对高低而非只看标签，把「核心优势」翻译成简历里的行为证据。

4. 课堂、社团与工作坊。无需登录、手机打开即用，投屏演示 + 各自作答，主持人按类型现场分组讨论。

5. 游戏内的轻量互动。千星沙箱版作为 UGC 关卡中的休闲交互点，单局 3 分钟，零服务端节点。

七、技术亮点

双端同源。题库、类型文案与判定参数在 Lua 与 JS 两侧逐条对应，改动需两端同步，保证结果口径一致。

沙箱端零节点。全部逻辑在客户端脚本内完成，不引入服务端节点图，也不依赖动态创建控件——53 个控件全部编辑期预置，规避了「只有模板控件的父节点才能动态创建」的限制。

接口可追溯。沙箱脚本的每个接口名都标注了官方文档章节；不确定的接口不猜，改为在文档中列为待核实项。

零依赖前端。无框架、无构建、无 CDN，单文件夹可直接静态托管；图标与图表全部手写 SVG，分享卡由 Canvas 现场绘制。

八、3 分钟演示脚本

  1. 0:00首页停 10 秒：一句话说清「15 题、3 分钟、五种动物」，指出这是双端作品。
  2. 0:20点「开始测评」，快速答 4–5 题，展示进度条与键盘作答（按 1–4）。
  3. 0:50点「上一题」展示可回看，再说明进度会自动保存、刷新可续答。
  4. 1:10直接跳到最后一题完成，进入结果页：先看类型，再看雷达图与极差解释。
  5. 1:50展开「答题回顾」，说明维度在结果页才公开的设计取舍。
  6. 2:10点「下载结果卡」，展示生成的 1080×1440 图片。
  7. 2:30切到「五型图鉴」看协作对照表，再切「作品介绍」讲双端实现与零依赖。
  8. 2:50收尾：强调纯本地计算、不收集数据，并说明沙箱版的 53 控件 / 657 行 Lua。
